## Main Finding: Process Not Followed (Guillaume's Feedback)

> "Le process n'est pas suivi, sinon tout va bien."

Two process violations occurred during Epic 2:

1. **Story 2.4 was marked `done` without a 3-layer code review.** This directly violates Epic 1 retro action #4 ("Always review before done — 3-layer review is non-negotiable"), which was the highest-priority process action item from Epic 1. The dev moved the story to `done` instead of `review`, bypassing the gate entirely.

2. **Epic 3 implementation started before the Epic 2 retrospective was complete.** The workflow requires the retro to run after an epic closes, before the next epic begins. This was skipped — Amelia started Story 3.1 while Epic 2 was still being wrapped up.

**Root cause:** Dev codes faster than reviews can keep up. The current workflow has no structural enforcement — the dev can mark a story `done` directly, bypassing the `review` status. This is the same class of problem doctor diagnoses in agent files: text-based process instructions are unreliable without structural enforcement.

**Corrective action for Epic 3 (see Action Item #1 below):** Dev marks stories as `review`, NOT `done`. Only the team lead marks `done` after the 3-layer review passes. This creates a structural gate that cannot be bypassed.

## What Went Well

- **Tech debt story (2.0) as a gate** — Creating a dedicated tech-debt story for the two HIGH retro items (frontmatter parsing, OpenRouter timeout) before starting new feature work was the right call. Both fixes were orthogonal to Story 2.1, and addressing them upfront prevented cascading failures in Stories 2.2 and 2.3 which process many files.
- **Frontmatter parsing fix landed cleanly** — The tolerant fallback parser in `extractFrontmatter()` now handles unquoted colons, multiline escaped descriptions, and empty frontmatter. All 22 testdata files parse without error. Test-first approach (failing tests added before implementation) validated the fix precisely.
- **OpenRouter timeout mirrored Ollama pattern** — `context.WithTimeout` + `http.NewRequestWithContext` applied consistently across both providers. Same 120s default, same configurable timeout field. Actionable error messages on timeout.
- **Registry package well-structured** — 12 entries with full research citations, embedded via `//go:embed`, local override at `.forgent/research-registry.yaml`, version tracking in `--debug` mode. Clean separation: `registry.go` (load/get/all), `updater.go` (download/checksum), `data/research-registry.yaml` (entries).
- **Context enricher reused existing scanner** — `internal/doctor/context/enricher.go` calls `scanner.ScanCodebase()` and implements 5 gap analysis categories (test coverage, structure awareness, key symbols, security match, stack awareness). No LLM calls — pure CODE skill as specified by ADR-4.
- **Directory analysis stayed sequential** — Despite the temptation to parallelize, Story 2.3 correctly kept sequential file processing. This avoided concurrency bugs (flagged as key risk in Epic 1 retro) while delivering FR8 (directory analysis with aggregate report).
- **Epic 1 retro action items mostly resolved** — 4 of 6 action items addressed (see tracking section below).
- **Test count grew significantly** — 197 doctor tests + 21 LLM tests, all passing. Full suite green: `go test ./... -count=1 -short` passes across 30 packages.
- **Story scoping discipline held** — Each story had explicit "What NOT to Build" sections. No undocumented scope creep (retro action #5 from Epic 1).
- **Code reviews continued finding real issues** — Stories 2.1, 2.2, 2.3 all reviewed. Winston's os.Exit(2) finding in RunE was a real bug (task #14).

## What Was Difficult

- **Dev outpaced review — Story 2.4 shipped without review** — Amelia's implementation velocity exceeded the team's review capacity. Story 2.4 was marked `done` without going through the mandatory 3-layer code review, directly violating Epic 1 retro action #4. This is the most significant process failure of the epic.
- **Epic 3 started before retro** — Implementation of Epic 3 began before the Epic 2 retrospective was complete. The workflow requires retro completion before starting the next epic, so that lessons learned can inform the next sprint. This was bypassed.
- **Retro items were initially unowned** — Neither the frontmatter parsing fix nor the OpenRouter timeout was scoped into any Epic 2 story. John's story files for 2.2/2.3 flagged them as prerequisites but nobody owned the work. Required SM escalation and a team-lead decision to create Story 2.0.
- **Story list expanded beyond original plan** — Epic 2 was planned as 3 stories (2.1, 2.2, 2.3) but shipped 5 (adding 2.0 tech debt and splitting 2.4 from original 2.3). The additional stories were justified but added scope beyond the original sprint estimate.
- **Story files still show ready-for-dev status** — The Dev Agent Record sections in story files (Agent Model Used, Completion Notes, File List) were not filled in after implementation. This makes retrospective data gathering harder — we have to infer from code and git history rather than reading story records.
- **doctor_test.go.bak still exists** — Epic 1 retro action #3 (MEDIUM) flagged this for cleanup. The file still exists at `internal/cmd/doctor_test.go.bak`. Not a blocker but indicates MEDIUM items slip through.
- **swebench_lite_30.jsonl.bak also exists** — Additional .bak file at `internal/bench/testdata/swebench_lite_30.jsonl.bak`. Same cleanup pattern.
