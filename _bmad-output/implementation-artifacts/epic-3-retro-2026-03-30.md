# Epic 3 Retrospective — Safe Agent Rewrite

## Main Finding: Process Violation Repeated — Review Gate Still Not Enforced

Epic 2 retro's **#1 CRITICAL action item** was: "Dev marks `review`, only lead marks `done`." This was explicitly stated as a structural gate that could not be bypassed. All three Epic 3 stories were marked `done` without going through the `review` status — the exact same violation that triggered the main finding in Epic 2's retro.

This is the **third consecutive epic** where stories shipped without the mandatory 3-layer code review:
- Epic 1: Story 1.6 marked done without review (discovered in Epic 1 retro)
- Epic 2: Story 2.4 marked done without review (Main Finding in Epic 2 retro)
- Epic 3: All 3 stories marked done without review (this retro)

**Root cause remains the same:** No structural enforcement of the workflow gate. The dev can mark stories `done` directly. The corrective action from Epic 2 retro was acknowledged but not implemented — the sprint-status.yaml workflow has no mechanism to prevent a dev from writing `done` instead of `review`.

**Escalation:** This is no longer an action item — it is a **systemic process failure**. The review gate must be enforced before Epic 4 begins. Options:
1. Pre-commit hook or CI check that rejects status transitions from `ready-for-dev`/`in-progress` directly to `done` (structural enforcement)
2. SM validates every status change before it lands (manual enforcement — fragile but immediate)
3. Accept that reviews will happen retroactively and budget time for them (pragmatic but undermines quality)

**Impact on Epic 3:** Epic 3 is the highest-risk epic so far — it writes user files via `--fix`, uses atomic file operations (SafeWrite), applies quality gates, and generates diffs for interactive selection. These are the features most likely to corrupt agent files if buggy. Shipping without review means unknown bugs may exist in file-writing code paths. A retroactive 3-layer review of all three stories is strongly recommended.

## What Went Well

- **All 3 stories delivered** — Story 3.1 (Defensive File Operations), Story 3.2 (Quality Gate Validation), and Story 3.3 (Interactive Rewrite Experience) all complete. The full `--fix` flow works end-to-end: analyze → select recommendations → rewrite → validate → SafeWrite.
- **54 new tests across 3 packages** — `internal/fileops/` (17 tests), `internal/doctor/validate/` (21 tests), `internal/doctor/rewrite/` (16 tests). All passing. This addressed the Epic 2 retro action item #5 ("Add tests for `internal/fileops/` before Story 3.1 uses it").
- **Test suite grew to 1,080 total tests** — Significant jump, though down from the 1,284 reported in the sprint review (test count may vary by `-short` flag or test build tags). All 33 packages pass `go test ./... -count=1 -short`.
- **SafeWrite implements atomic write pattern correctly** — Backup creation, temp file write, rename into place. Lock-based concurrency protection. Signal handling for Ctrl+C safety. Cleanup of old backups. This is a solid defensive file operations foundation.
- **Quality gate is fail-closed with 4 checks** — Frontmatter validity, field preservation, markdown structure, section preservation. Plus diff-size sanity check with `--force` bypass. The gate runs independently of the LLM — deterministic validation, no network calls.
- **FormatParser.Validate() added to all 3 parsers** — Claude, Copilot, and Forgent parsers all implement the `Validate(original, rewritten []byte) error` method as specified in ADR-6. Format-specific validation integrated into the quality gate pipeline.
- **Interactive selection with TTY awareness** — Numbered list display, comma-separated selection ("1,3,5"), non-TTY fallback (apply all), edge case handling (out of range, empty, duplicates). Builds on the TTY-aware output pattern established in Epic 1.
- **Diff generation with colorized output** — Unified diff format with context lines, fatih/color for TTY mode, plain mode for CI/pipe. Clean separation in `rewrite/diff.go`.
- **Story scoping discipline held again** — All 3 stories had "What NOT to Build" sections. No batch rewrite for directory mode, no full diff algorithm (Myers/patience), no undo history beyond single `.bak`, no auto-apply. Scope stayed clean.

## What Was Difficult

- **Review gate not enforced (AGAIN)** — See Main Finding above. This is the third epic with the same violation. The corrective action from Epic 2 retro was defined but not structurally implemented.
- **Fixes took multiple messages to complete** — Implementation required multiple rounds of back-and-forth to get things done. This suggests either stories were under-specified, or the dev needed more context upfront. Consider adding more explicit implementation guidance in story Dev Notes.
- **Idle notifications were misleading** — System notifications indicated idle status when work was actually in progress. This created false signals for the SM and team lead, making it harder to track real progress. The notification system needs calibration.
- **Dev Agent Records still empty** — All 3 story files (3.1, 3.2, 3.3) have placeholder `{{agent_model_name_version}}` in the Dev Agent Record section. Completion Notes and File Lists are empty. This is the same gap flagged in Epic 2 retro action item #7. Three epics in a row with no story metadata.
- **`--restore` not wired into CLI** — `fileops.Restore()` function exists and is tested, but Story 3.3 did not wire a `--restore` flag into the CLI doctor command. The sprint review lists "Backup/restore via `--restore`" as a deliverable, but the flag does not exist. This is a gap between documentation and implementation.
- **No corpus test for quality gate** — Story 3.2 AC #4 required "Test corpus of >= 30 real Claude files and >= 30 real Copilot files — 100% of rewrites pass all quality gate checks." There is no `gate_corpus_test.go` file. The quality gate has unit tests (21 tests) but not the corpus-level validation specified in the acceptance criteria.
- **Both .bak files still exist** — `internal/cmd/doctor_test.go.bak` and `internal/bench/testdata/swebench_lite_30.jsonl.bak` are still present. This was first flagged in Epic 1 retro (action #3, LOW priority), carried through Epic 2, and now into Epic 4. Three epics without resolution.

## Preparation for Epic 4

**Epic 4: Doctor as Forgent Runtime Agent (KEYSTONE)** — 3 stories:
- 4.1: Doctor skill and agent YAML definitions (5 skill YAMLs, 1 agent YAML)
- 4.2: Embedded YAML and runtime DAG construction (`//go:embed`, runtime DAG from specs)
- 4.3: Runtime error handling and diagnostics (equivalence testing, fallback, observability)

**Key risk:** Equivalence testing — the DAG-based doctor must produce identical output to the current direct-Go implementation. This requires running both paths on the same inputs and comparing results. If the quality gate was never corpus-tested (action #3 above), equivalence testing has no trusted baseline.

**Dependencies on Epic 3:** `--fix` flow (rewrite → validate → SafeWrite) must be stable and reviewed. If Epic 3 code has unreviewed bugs (action #2 above), they will be baked into the DAG pipeline.

**DAG engine readiness:** `pkg/dag/` is mature (42 tests, race-clean, supports auto-wiring, layers, router, retry). The challenge is mapping doctor's current procedural flow into a DAG topology with skills at each node.
