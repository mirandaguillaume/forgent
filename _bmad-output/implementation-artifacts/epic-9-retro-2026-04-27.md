## What Went Well

### 1. Batch-apply discipline
Each of the 3 stories followed the same cycle: implement → 3-agent parallel review → triage → batch-apply all patches → done. Tight cycle, stable state at every checkpoint. 17/17 patches applied with zero regression.

### 2. Zero scope creep
All 3 stories shipped exactly what was in `epics.md` (Stories 6.1, 6.2, 6.3 of original Epic 6 spec). No accumulated extras, no half-finished features. ACs → Tasks → Tests, 1:1 mapping throughout.

### 3. Review gate 100% sustained
Action #6 from Epic 5 retro was "every story gets a code review". Epic 9 maintained 3/3 compliance. The 2 HIGH bugs caught (P1 9-2 dotfile, P1 9-3 flaky test) prove the review gate catches issues CI would miss.

### 4. Deep API exploration over stubs
When `bc.GetFlagCompletions(...)` didn't exist in Cobra 1.10.2, the team dug into Cobra source until finding the hidden `__complete` subcommand instead of stubbing. Pattern worth keeping: learn the API, don't fake it.

### 5. Disciplined ignore of pre-existing failures
2 pre-existing test failures (`context/enricher_test.go`, `static/drift_test.go`, both `/tmp` env-related) were noticed and explicitly NOT touched. Focus discipline — no yak-shaving inside the epic boundary.

## What Didn't Go Well

### 1. "Swallow & continue" pattern is systemic
4 cases across 3 stories:
- 9-1 P2: `cfgErr` silently swallowed
- 9-1 P3: Permission errors treated as not-found
- 9-2 P4: `_, _ = Write()` ignored
- 9-3 P3: `_ = RegisterFlagCompletionFunc(...)` ignored

**Root cause:** Default reflex when a function returns `error` is to discard it to avoid breaking the binary. Charlie wrote 3/4. Not an oversight anymore — installed anti-pattern.

### 2. Cobra subtleties trapped every story
Every story lost time on a Cobra gotcha:
- 9-1: env precedence confusing `unset` with `"false"`/`"0"`
- 9-2: needing `cmd.OutOrStdout()` instead of `os.Stdout` for testability
- 9-3: `Run` vs `RunE`, `__complete`, sticky `--help` flag across tests, `SilenceErrors` semantics

Cobra has 15 years of API surface. Each gotcha cost ~30min-1h of debug. Documenting these would compound.

### 3. False-positive rate on review agents
- 9-2: 12 dismissed (mostly Acceptance Auditor false negatives on test files present)
- 9-3: 10 dismissed (mostly Blind Hunter hallucinations on Cobra mechanics)

22 dismissed across 38 total findings = **58% dismissal rate**. The 3-angle approach has value (Edge Case Hunter caught the real bug Blind Hunter missed), but human attention cost is real.

### 4. Test isolation via shared `rootCmd`
Package-level `rootCmd` causes order-dependent test failures (sticky `--help` flag was the visible symptom). The `resetBuildHelpFlag()` helper is a workaround, not a fix. Pattern propagates.

### 5. Deferred work triage missed AGAIN
Action #4 from Epic 5 retro was "triage 34 deferred items". Not done. Epic 9 added 6 more (5 from 9-3, 1 from 9-2). Cumulative now 40+. Third consecutive epic without triage.

### 6. Tracking comments leaked to prod code
9-3 P6 found `// P3 Task 3.3:` comment in `build.go`. Story-tracking metadata violates the CLAUDE.md rule "Don't reference the current task, fix, or callers". Likely present in other Epic 9 code.

## Significant Discoveries

The retrospective surfaced two findings that affect Epic 10 sequencing (but not its plan):

1. **"Swallow & continue" risks Epic 10 security correctness.** Epic 10 adds file access control, network sandbox, and output schema validation — code that makes security decisions. Continuing to swallow errors silently will ship security holes by design.

2. **Test isolation will corrupt Epic 10 telemetry.** Story 10-6 adds violation telemetry. Shared `rootCmd` state across tests will produce false positives in violation counters.

**Recommendation:** Actions #1 (audit), #3 (triage), and #5 (test isolation) should be **prerequisites for Epic 10 stories 10-3 onward**, not nice-to-haves. Epic 10 itself doesn't need re-planning, just re-sequencing.

## Lessons Learned

1. **Batch-apply discipline scales.** 17 patches across 3 stories, all applied, zero regression. Worth keeping as the default cycle.

2. **API depth pays back.** Reading Cobra source to find `__complete` instead of stubbing it cost 30min and produced a real test. Stubbing would have produced a fake test.

3. **Anti-patterns install themselves through repetition.** "Swallow & continue" wasn't decided — it accumulated. Once 4 cases land, it's the new default. Catch them before the 5th.

4. **Review gate 100% pays.** 2 HIGH bugs that CI would not have caught. The cost-benefit of code review is decisively positive.

5. **Deferred work without triage isn't deferred — it's lost.** 3 epics of accumulating without review. Future-you can't make decisions on 40+ unstructured items.
